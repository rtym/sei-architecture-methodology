Architecture: Personal Finance Tracker

  • System: Web app for individuals to track income, expenses and savings goals.

1. Introduction

A mobile-web personal finance tracker. This document is the ADD 3.0 working architecture after iteration 1 (overall structure, security, availability) and iteration 2 (dashboard read path). Drivers: ../drivers/README.md.

2. Context diagram

Diagram

Description

A single external dependency at launch: a transactional email provider. Everything else is owned by the system, keeping the SOC 2 (CON-4) surface small.

4. Container diagram

Diagram

Description

The API service is the single write path and the single place tenant scoping (SQA-1) is enforced. The Redis read cache serves the dashboard (PQA-1); it is a performance element, not a system of record, so its loss degrades latency but not correctness (AQA-1).

5. Component diagrams

API Service

Diagram

Description

Every request passes through the Tenant Guard before any service runs, so cross-tenant access (SQA-1) is structurally prevented rather than checked per-endpoint.

6. Sequence diagrams

On a cache hit the database is not touched, which is the common path and keeps p95 under the 1.5 s budget (PQA-1). On a miss the API recomputes from tenant-scoped rows and repopulates the cache; a stale cache is bounded by the 15-minute TTL.

7. Deployment diagram

Diagram

Description

The API runs as stateless replicas spread across two AZs behind the platform load balancer, and the data tier uses managed primary/standby with automated failover — together these meet AQA-1 (single-AZ failure recovers < 60 s) within the CON-3 low-cost-tier constraint.

DecisionRationale (cite driver IDs)Alternatives discarded
